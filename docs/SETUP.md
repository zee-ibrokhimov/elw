# Что настроить перед запуском

Восемь шагов, суммарно около часа. Порядок не случайный: шаг 0 определяет
значения в шагах 1 и 7, а шаг 8 — самый долгий, поэтому запускается фоном.

Все значения вписываются в файл `.env` в корне проекта — он уже создан,
секреты в нём сгенерированы, незаполненные места помечены словом `ЗАПОЛНИ`.

Проверить, что ничего не пропущено:

```bash
grep ЗАПОЛНИ .env
```

В PowerShell:

```bash
Select-String -Path .env -Pattern 'ЗАПОЛНИ'
```

---

## Шаг 0. Выбрать домен ⏱ 1 мин

Нужен поддомен, который потом заведём в Cloudflare Tunnel, например
`tutorsync.твойдомен.tld`. Наружу будет торчать только процесс `web` с двумя
эндпоинтами — приёмом уведомлений Google и колбэком OAuth.

В `.env` заменить `ЗАПОЛНИ.example.com` на этот домен в двух местах:
`PUBLIC_BASE_URL` и `GOOGLE_OAUTH_REDIRECT_URI`.

Домен нужен уже сейчас, потому что Google требует точного совпадения
redirect URI, а он задаётся до первого запуска.

## Шаг 1. Google Cloud: проект и OAuth-клиент ⏱ 15 мин

Самый длинный шаг и единственный, где легко сделать незаметную ошибку,
из-за которой сервис проработает ровно семь дней и тихо умрёт.

### 1.1 Проект и API

1. [console.cloud.google.com](https://console.cloud.google.com) → выпадающий
   список проектов сверху → **New project** → имя `tutorsync` → **Create**.
2. Убедиться, что вверху выбран именно этот проект.
3. **APIs & Services → Library** → найти **Google Calendar API** → **Enable**.

### 1.2 Экран согласия

В новом интерфейсе это раздел **Google Auth Platform**, в старом —
**APIs & Services → OAuth consent screen**.

1. **Audience / User type**: **External**. (Internal доступен только на Google
   Workspace; для обычного Gmail его в списке не будет.)
2. Заполнить название приложения, свою почту как support email и как
   контакт разработчика.
3. **Data access / Scopes** → **Add or remove scopes** → добавить вручную:

   ```
   https://www.googleapis.com/auth/calendar
   ```

   Это чувствительный (sensitive) scope, но не ограниченный (restricted) —
   проходить проверку Google не нужно.
4. **Test users** → добавить свой собственный Gmail.

### 1.3 Публикация — не пропускать

На странице **Audience** (в старом интерфейсе — внизу OAuth consent screen)
нажать **PUBLISH APP** и подтвердить. Статус должен смениться с
**Testing** на **In production**.

Зачем: у приложения в статусе Testing Google отзывает refresh-токен через
**7 дней**. Сервис при этом не падает — он просто перестаёт видеть календарь,
и узнаёшь ты об этом, когда ученик придёт на урок, которого нет в расписании.
Это самая частая причина смерти таких интеграций.

Верификацию проходить не нужно. При первой авторизации Google покажет экран
«Google hasn't verified this app» — нажать **Advanced** → **Go to tutorsync
(unsafe)**. Для приложения, которым пользуешься только ты, это нормально:
ограничение непроверенного приложения — 100 пользователей, нам нужен один.

### 1.4 Клиент

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**.
2. **Application type**: **Web application**.
3. **Authorized redirect URIs** → **Add URI**:

   ```
   https://ТВОЙ-ДОМЕН/oauth/callback
   ```

   Слово в слово как в `GOOGLE_OAUTH_REDIRECT_URI`, включая `https` и
   отсутствие слэша на конце. Расхождение в один символ даёт ошибку
   `redirect_uri_mismatch`.
4. **Create** → скопировать **Client ID** и **Client secret**.

**В `.env`:** `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

> Саму авторизацию (переход по ссылке и выдачу доступа) делать **сейчас не надо** —
> она пройдёт после деплоя, когда домен заработает.

## Шаг 2. Три календаря ⏱ 5 мин

В [calendar.google.com](https://calendar.google.com) слева, рядом с
**Other calendars**, нажать **+** → **Create new calendar**. Создать три:

| Название | Что в нём | Кто пишет |
|---|---|---|
| `Preply` | уроки с Preply | сервис, из писем |
| `Private` | уроки частных учеников | сервис, из бота |
| `Buffers` | служебные блоки вокруг уроков | сервис |

Для каждого: **Settings and sharing** → прокрутить до **Integrate calendar** →
скопировать **Calendar ID** (выглядит как
`c_a1b2c3…@group.calendar.google.com`).

**В `.env`:** `GCAL_CALENDAR_PREPLY`, `GCAL_CALENDAR_PRIVATE`,
`GCAL_CALENDAR_BUFFERS`.

Если хочешь, чтобы личные дела тоже закрывали слоты в боте, добавь их
календари в `EXTRA_BUSY_CALENDAR_IDS` через запятую. Основной календарь
обозначается словом `primary`. Сервис в эти календари только читает.

## Шаг 3. Почта: пароль приложения и фильтр ⏱ 5 мин

Читаем по IMAP, а не через Gmail API — так не упираемся в проверку
ограниченных scope'ов, которая для чтения почты обязательна.

1. Включить двухфакторную аутентификацию в Google-аккаунте, если её нет —
   без неё пароли приложений недоступны.
2. [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords) →
   создать пароль с именем `tutorsync` → скопировать 16 символов
   (пробелы можно не убирать, можно убрать — работает и так).
3. В Gmail: **Настройки → Фильтры и заблокированные адреса → Создать фильтр** →
   поле **От**: `preply.com` → **Создать фильтр** → отметить
   **Применить ярлык** → новый ярлык `Preply`.

   Ярлык Gmail — это папка IMAP, воркер слушает именно её и не перебирает
   весь ящик.

**В `.env`:** `IMAP_USER` (адрес почты), `IMAP_PASSWORD` (пароль приложения,
**не** основной пароль от аккаунта).

## Шаг 4. Telegram ⏱ 5 мин

1. [@BotFather](https://t.me/BotFather) → `/newbot` → имя и username бота →
   скопировать токен вида `1234567890:AA…`.
2. [@userinfobot](https://t.me/userinfobot) → написать ему что угодно →
   он ответит твоим числовым `Id`.

**В `.env`:** `TELEGRAM_BOT_TOKEN`, `ADMIN_TELEGRAM_IDS` (число из второго пункта).

`ADMIN_TELEGRAM_IDS` — это whitelist: только с этих аккаунтов работают
админ-команды, очередь ручных задач и алерты. Всё остальное — интерфейс ученика.

## Шаг 5. Postgres ⏱ 5 мин

В Coolify: **New Resource → Database → PostgreSQL 16**. После создания взять
строку подключения из вкладки ресурса.

**В `.env`:** `DATABASE_URL`, в формате

```
postgresql+asyncpg://ПОЛЬЗОВАТЕЛЬ:ПАРОЛЬ@ХОСТ:5432/БАЗА
```

Префикс `postgresql+asyncpg://` обязателен — Coolify отдаёт строку в виде
`postgres://…`, её нужно переписать.

## Шаг 6. Репозиторий ⏱ 3 мин

Coolify деплоит из git. Создать **пустой приватный** репозиторий на GitHub
(без README, без .gitignore — они уже есть локально) и прислать ссылку.

Приватный, а не публичный: в истории будут фикстуры писем, пусть и
обезличенные, и настройки твоего расписания.

---

## Шаг 7. Cloudflare Tunnel ⏱ 5 мин

Маршрут: выбранный на шаге 0 поддомен → `http://web:8080`.

Настроить можно уже сейчас, работать начнёт после деплоя. Наружу открыты
ровно два пути:

* `/webhook/gcal/<секрет>` — приём push-уведомлений Google;
* `/oauth/callback` — однократная авторизация Google.

Процессы `bot` и `worker` наружу не смотрят вообще: бот забирает сообщения
long polling'ом, поэтому публичный адрес ему не нужен.

## Шаг 8. Письма Preply ⏱ 10 мин, начинать сразу

Без них не пишется парсер, и это единственное, что нельзя ускорить.

Нужны три файла `.eml` в папке `samples/`:

| Файл | Событие |
|---|---|
| `booked.eml` | урок забронирован |
| `rescheduled.eml` | урок перенесён |
| `cancelled.eml` | урок отменён |

Как выгрузить в Gmail: открыть письмо → меню «⋮» справа → **Показать
оригинал** → **Скачать сообщение**.

Имя ученика можно заменить на вымышленное. **Не менять** заголовки письма,
адрес отправителя, вёрстку и формат даты — парсер цепляется именно за них.

Если есть письма про пробный урок и про пакет из нескольких уроков — добавь
и их: структура у них другая, и парсер должен уметь вернуть несколько
событий из одного письма.

Папка `samples/` целиком в `.gitignore`. Обезличенные фикстуры для тестов
лягут отдельно, в `tests/fixtures/emails/`.

Заодно посмотри в настройках Preply, какой у тебя стоит часовой пояс — от
него зависит, как трактовать время в письмах.

---

## Чего сейчас делать не надо

* **Авторизовываться в Google.** Ссылка появится после деплоя, когда заработает
  домен.
* **Подключать интеграцию Preply ↔ Google Calendar.** Сервис стартует с
  `PREPLY_GCAL_LINKED=false` и работает через очередь ручных задач.
  Переключим, когда будет что синхронизировать.
* **Ставить что-либо на свою машину.** Всё крутится на сервере.
