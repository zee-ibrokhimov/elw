# tutorsync

Синхронизация расписания репетитора между тремя системами: **Preply**, **Google
Календарь** и **Telegram-бот для бронирования**. Self-hosted, один Docker-образ,
Postgres, никаких внешних очередей.

> **Состояние: в разработке.** Готовы каркас, схема базы, авторизация в Google
> и запись событий в календарь через очередь `outbox`. Приём писем Preply,
> сверка расписания и бронирование подключаются следующими этапами —
> см. [«План»](#план).
>
> Подключение Google-аккаунта: отправить боту `/connect_google` и открыть
> выданную ссылку. Ссылка живёт 10 минут и выдаётся только админам.

## Как это устроено

Источник истины по расписанию — **база сервиса**. Google Календарь является её
проекцией: он нужен, чтобы расписание было видно в телефоне и чтобы Preply мог
узнать о занятости. При расхождении побеждает то, что уже подтверждено ученику.

```
Preply ──письмо──> IMAP ─┐
Telegram-бот ────────────┼──> БД ──> Google Календарь ──> Preply
Ты, /block ──────────────┘    │      (Preply/Private/Buffers)
                              └──> Telegram: карточки, алерты, очередь задач
```

Три процесса из одного образа, роль задаётся переменной `ROLE`:

| Процесс | Что делает | Смотрит наружу |
|---|---|---|
| `web` | приём push-уведомлений Google, колбэк OAuth, `/healthz` | да, через Cloudflare Tunnel |
| `bot` | Telegram, long polling | нет |
| `worker` | планировщик, IMAP, сверка расписания, отправка отложенных эффектов | нет |

Два решения, определяющие всё остальное:

**Outbox.** Обращения к Google и Telegram ставятся в очередь в таблице `outbox`
**в той же транзакции**, что и запись расписания, а выполняются отдельным
воркером с ретраями. Коммит базы и вызов чужого API атомарными быть не могут,
поэтому наружу изнутри транзакции не ходим вообще — иначе рано или поздно
появится урок, записанный в базу, но отсутствующий в календаре. Это же заменяет
Redis с Celery обычной таблицей и `SELECT ... FOR UPDATE SKIP LOCKED`.

**EXCLUDE-констрейнт.** Непересечение уроков держит база, а не код:

```sql
EXCLUDE USING gist (tstzrange(start_utc, end_utc, '[)') WITH &&)
WHERE (role = 'lesson' AND active AND NOT conflict_accepted)
```

Предикат важен целиком: буферы соседних уроков при плотной сетке законно
накладываются друг на друга, а оплаченный урок с Preply принимается в базу даже
поверх существующей брони — отменить его нельзя, поэтому вместо отказа заводится
запись в `conflicts` и уходит алерт.

## Настройка

Пошагово, с путями по меню — **[docs/SETUP.md](docs/SETUP.md)**. Восемь шагов,
около часа.

Все значения живут в `.env` (в репозиторий не попадает). Полный список
переменных с комментариями — в [`.env.example`](.env.example).

Два места, где ошибка стоит дорого:

* **Статус OAuth-приложения должен быть `In production`.** В статусе `Testing`
  Google отзывает refresh-токен через 7 дней. Сервис при этом не падает — он
  просто перестаёт видеть календарь, и узнаёшь об этом, когда ученик приходит
  на урок, которого нет в расписании.
* **`GOOGLE_OAUTH_REDIRECT_URI` должен слово в слово совпадать** с тем, что
  прописано в Cloud Console, включая схему и отсутствие слэша на конце.

## Запуск

Локально:

```bash
docker compose up --build
```

Миграции применяются отдельным разовым контейнером `migrate` — три сервиса не
должны гоняться за одну и ту же блокировку Alembic на старте.

Тесты:

```bash
docker compose run --rm tests
```

Тесты на пересечение интервалов идут против настоящего Postgres: на SQLite они
проверяли бы не тот механизм, что работает в проде.

### Coolify

Три ресурса из одного репозитория, различаются только переменной `ROLE`
(`web`, `bot`, `worker`) — плюс отдельный ресурс PostgreSQL. Наружу через
Cloudflare Tunnel публикуется только `web`, порт 8080. Подробности — в
[docs/SETUP.md](docs/SETUP.md).

## Ограничения

Честно и без смягчений.

**У Preply нет API, вебхуков и ICS-экспорта.** Есть ровно два легальных канала:
письма-уведомления наружу (читаем по IMAP) и штатное подключение Google
Календаря внутрь. Всё остальное — браузерная автоматизация и неофициальные
эндпоинты — в этом проекте не используется сознательно.

**Занятость попадает в Preply не мгновенно.** Даже с подключённой нативной
интеграцией Preply перечитывает Google Календарь с задержкой в несколько минут.
Пока `PREPLY_GCAL_LINKED=false`, автоматической передачи нет вообще: сервис
присылает карточку «закрой это время на Preply» и напоминает, пока не
подтвердишь.

**Отсюда — окно двойного бронирования.** Между моментом, когда частный ученик
занял слот в боте, и моментом, когда Preply об этом узнал, ученик с Preply может
занять то же время. Сервис такой конфликт обнаруживает и **ничего не отменяет
автоматически**: оба урока остаются в базе, обе брони приходят в Telegram с
кнопками решения. Автоотмена оплаченного урока недопустима, а угадать, кем
пожертвовать, программа не может.

Уменьшить окно можно, но не закрыть: увеличить `BUFFER_BEFORE_MIN` и
`BUFFER_AFTER_MIN`, либо держать на Preply заведомо более узкие рабочие часы,
чем в боте.

**Формат писем Preply может измениться без предупреждения.** Парсеры вынесены в
отдельный модуль со снапшот-тестами на реальных шаблонах, так что починка — это
правка одного файла и добавление фикстуры. Нераспознанное письмо не теряется и
не проглатывается: оно целиком ложится в таблицу `dead_letters`, а в Telegram
уходит алерт с его текстом. Худший сценарий — урок не попал в расписание, и ты
узнаёшь об этом сразу, а не от ученика.

**Ученики с Preply не существуют для сервиса как люди.** Из письма приходит
только имя, поэтому у такого урока нет привязки к профилю и нет возможности
написать ученику. Напоминания им шлёт сама площадка.

## План

| Этап | Содержание | Статус |
|---|---|---|
| 1 | Каркас, конфиг, схема БД, миграции, репозитории, расчёт слотов | в работе |
